# インフラエンジニアのための「プログラムが動く仕組み」入門

普段、何気なく使っている `yum install` や `docker run` や `systemctl start nginx` など、これらコマンドの裏側で、コンピュータやサーバは何をしているのでしょうか？

このリポジトリは、主に**インフラ構築・運用 （オンプレ・クラウド問わず） をメインに行ってきたエンジニア**を対象に、ソースコードが実行可能なプログラムになり、パッケージとして配布され、最終的にプロセスとしてポートをリッスンするまでの流れを、実際に手を動かしながら理解するためのハンズオン資料です。

これまで「ブラックボックス」だったアプリケーションの内部動作の基本を知ることで、トラブルシューティングの精度向上や、より効率的なコンテナイメージの作成、そしてシステム全体を俯瞰する解像度を高めることを目的としています。

このリポジトリでは例に C 言語を用いてますが、「なんかプログラムが書いてあるなー」と思っているだけで大丈夫です。

## コンテンツ一覧

### [Chapter 01: コンパイルについて](./Chapter01.md)

ソースコード (テキスト) が、なぜコンピュータで実行できるのか？コンパイラ (`cc`, `gcc`) が行っている「翻訳」のプロセスを体験します。

### [Chapter 02: ビルドについて](./Chapter02.md)

プログラムが大規模になると、手動でのコンパイルは困難になります。`make` コマンドを使って、依存関係を管理しつつ自動的に実行ファイルを生成する「ビルド」の仕組みを学びます。

### [Chapter 03: パッケージについて](./Chapter03.md)

作ったプログラムを他のサーバーでも簡単に使えるようにする「パッケージング」。RPM や DEB、そして `apt` や `yum` が裏でどのように依存関係を解決しているのかを解説します。

### [Chapter 04: コンテナ化について](./Chapter04.md)

現代の標準である Docker コンテナ。「コンテナイメージ」の実体は何か？ `Dockerfile` は何をしているのか？これまでのビルドの知識を使って、アプリケーションを OS 環境ごとパッケージングします。

### [Chapter 05: 簡易 Web サーバーを作ってみる](./Chapter05.md)

インフラエンジニアが最も気にする「ポートの Listen」。実際に C 言語でソケットを扱い、`bind` し `listen` するプログラムを書くことで、「Web サーバが起動している」という状態が、OS レベルで何を意味するのかを理解します。

## 対象読者

- Linux の基本操作 (ファイルの操作、コマンド実行) ができる方
- 普段ミドルウェアやアプリケーションを利用・構築する側の方
- プログラムが動く低レイヤーの仕組みに興味がある方

## 実行環境

- Linux 環境 (Debian/Ubuntu, CentOS/RHEL など)
- C コンパイラ (gcc)
- make
- Docker (Chapter 04 以降)
